# Model Evaludation - JTBD

## JTBD: DocSumo Document Evaluation System (inspired by Extend)
**Core outcome:** _Know—quantitatively—how accurate my extraction+classification is for a given document type/model/config, where it fails, and what to fix next._
* * *
### 1) Create a repeatable evaluation set (the “golden” dataset)
1.1 **\[Critical\]** When I’m rolling out extraction for a document type, I want to create an **evaluation set of representative documents** (sample coverage by layouts, scan quality, edge cases), so I can measure accuracy consistently over time. _(Extend “Evaluation Sets”)_ [Extend Developer Documentation+1](https://docs.extend.ai/product/evaluation/creating-evaluation-sets?utm_source=chatgpt.com)
1.2 **\[Critical\]** When I add documents to an evaluation set, I want to **preserve the exact input artifacts** (original file, pages, splits, metadata), so results are reproducible and comparable. _(Extend eval sets are “files + expected outputs”)_ [Extend Developer Documentation](https://docs.extend.ai/developers/api-reference/evaluation-set-endpoints/get-evaluation-set?utm_source=chatgpt.com)
1.3 **\[High\]** When I’m curating the set, I want to tag documents by **scenario labels** (template/layout variant, lender/customer, language, scan quality), so I can slice accuracy by segment. _(Aligns with vendor “dataset diagnostics / factors” style reporting)_ [UiPath Documentation+1](https://docs.uipath.com/document-understanding/automation-cloud-dedicated/latest/user-guide/measure?utm_source=chatgpt.com)
1.4 **\[Low\]** When I’m managing evaluation sets, I want versioning, ownership, and notes (why docs were added/removed), so the dataset doesn’t drift silently. _(Common MLOps evaluation-set practice)_ [doc.dataiku.com](https://doc.dataiku.com/dss/latest/mlops/model-evaluations/index.html?utm_source=chatgpt.com)
* * *
### 2) Capture ground truth and “expected outputs”
2.1 **\[Critical\]** When a document is in an evaluation set, I want to store **expected outputs (ground truth)** per field/table, so I can compute objective accuracy metrics. _(Extend eval sets include “expected outputs”; Google DocAI compares predictions vs annotations)_ [Extend Developer Documentation+1](https://docs.extend.ai/developers/api-reference/evaluation-set-endpoints/get-evaluation-set?utm_source=chatgpt.com)
2.2 **\[Critical\]** When I create ground truth, I want it to be **reviewable and auditable** (who labeled, when, what changed), so evaluation results are trusted in audits. _(Regulated workflow needs traceability; vendors emphasize QA baselines)_ [help.hyperscience.ai](https://help.hyperscience.ai/v42/docs/monitoring-model-performance?utm_source=chatgpt.com)
2.3 **\[High\]** When the output has tables/line-items, I want table-aware labeling (row alignment rules / matching strategy), so table metrics are meaningful. _(Closest analogue: extraction accuracy reporting paradigms in vendor eval dashboards)_ [UiPath Documentation+1](https://docs.uipath.com/document-understanding/automation-cloud/latest/user-guide/measure?utm_source=chatgpt.com)
2.4 **\[Low\]** When labeling is expensive, I want lightweight import/export (CSV/JSON) for ground truth, so I can label outside and sync back. _(Extend has eval set endpoints; many platforms support dataset workflows)_ [Extend Developer Documentation](https://docs.extend.ai/developers/api-reference/evaluation-set-endpoints/get-evaluation-set?utm_source=chatgpt.com)
* * *
### 3) Run evaluation on demand (and rerun later)
3.1 **\[Critical\]** When I’m ready to test, I want to run the evaluation set against a **specific model/config/version**, so I can attribute performance to the exact change I shipped. _(UiPath supports model version selection; Google DocAI evaluates processor versions)_ [UiPath Documentation+1](https://docs.uipath.com/document-understanding/automation-cloud/latest/user-guide/measure?utm_source=chatgpt.com)
3.2 **\[Critical\]** When evaluation runs, I want deterministic settings (confidence thresholds, OCR options, post-processing rules) captured with results, so comparisons are valid. _(Confidence/threshold settings materially change automation behavior)_ [developers.rossum.ai+1](https://developers.rossum.ai/docs/using-ai-confidence-thresholds-for-automation-in-rossum?utm_source=chatgpt.com)
3.3 **\[High\]** When I rerun evaluation, I want “compare runs” across versions/time, so I can detect regression or improvement quickly. _(UiPath “Measure” + version comparison patterns; MLOps comparisons)_ [UiPath Documentation+1](https://docs.uipath.com/document-understanding/automation-cloud/latest/user-guide/measure?utm_source=chatgpt.com)
3.4 **\[Low\]** When runs are large, I want retries/resume + partial results, so evaluation is robust. _(General eval-set runner pattern)_ [Inspect](https://inspect.aisi.org.uk/eval-sets.html?utm_source=chatgpt.com)
* * *
### 4) Compute the metrics that matter (field + document + workflow)
4.1 **\[Critical\]** When results are computed, I want **field-level accuracy** (exact match / tolerance rules) and **classification metrics** , so I can quantify performance beyond “confidence.” _(Google DocAI evaluate; UiPath Measure; ABBYY classification stats)_ [Google Cloud Documentation+2UiPath Documentation+2](https://docs.cloud.google.com/document-ai/docs/evaluate?utm_source=chatgpt.com)
4.2 **\[Critical\]** When metrics are shown, I want “**pass/fail**” against acceptance criteria (e.g., required fields >= X%), so I can decide go/no-go. _(UiPath “factors / recommendations” + evaluation dashboards; Hyperscience baseline approach)_ [UiPath Documentation+1](https://docs.uipath.com/document-understanding/automation-suite/2024.10/user-guide/measure?utm_source=chatgpt.com)
4.3 **\[High\]** When confidence is available, I want to see **accuracy vs confidence threshold** tradeoffs, so I can set safe auto-accept / human-review cutoffs. _(Rossum thresholds; UiPath label threshold stats; Nanonets threshold calibration; Mindee routing guidance)_ [docs.mindee.com+3developers.rossum.ai+3UiPath Documentation+3](https://developers.rossum.ai/docs/using-ai-confidence-thresholds-for-automation-in-rossum?utm_source=chatgpt.com)
4.4 **\[Low\]** When reporting overall value, I want “business metrics” proxies (automation rate, % routed to review, time saved), so stakeholders see ROI. _(Hyperscience talks about accuracy + automation trends)_ [help.hyperscience.ai](https://help.hyperscience.ai/v42/docs/monitoring-model-performance?utm_source=chatgpt.com)
* * *
### 5) Diagnose failures fast (what broke, why, and how often)
5.1 **\[Critical\]** When accuracy drops, I want to quickly see **top failing fields**, error types (missing/wrong/format), and example documents, so I can fix the right thing first. _(Vendor “measure/diagnostics” style)_ [UiPath Documentation+1](https://docs.uipath.com/document-understanding/automation-cloud-dedicated/latest/user-guide/measure?utm_source=chatgpt.com)
5.2 **\[High\]** When issues cluster, I want **slicing** by tags (layout variant, scan quality, language), so I can isolate root causes and avoid overfitting. _(Dataset diagnostics patterns)_ [UiPath Documentation+1](https://docs.uipath.com/document-understanding/automation-suite/2024.10/user-guide/measure?utm_source=chatgpt.com)
5.3 **\[High\]** When classification is involved, I want a **confusion-matrix view** (what gets confused with what), so I can target training data for the most common confusions. _(ABBYY confusion matrix)_ [help.abbyy.com](https://help.abbyy.com/en-us/flexicapture/12/standalone_administrator/classify_fc_statistics?utm_source=chatgpt.com)
5.4 **\[Low\]** When reviewing outputs, I want optional visual overlays / highlight mismatches, so humans can validate quickly. _(Common in validation UIs; not core to evaluation first)_ [Rossum.ai](https://rossum.ai/help/article/automation-process-in-rossum/?utm_source=chatgpt.com)
* * *
### 6) Turn findings into actions (close the loop)
6.1 **\[Critical\]** When I find systematic errors, I want to convert failures into **labeled training/QA tasks** (add to dataset, route to review), so the system improves every iteration. _(Hyperscience recommends more QA + retrain; Mindee suggests routing low-confidence to human validation and improvement loop)_ [help.hyperscience.ai+1](https://help.hyperscience.ai/v42/docs/evaluating-model-training-results?utm_source=chatgpt.com)
6.2 **\[High\]** When I’m unsure about automation, I want to recommend **threshold changes** (auto-accept vs review) based on eval results, so risk is controlled. _(Rossum + UiPath threshold tuning)_ [developers.rossum.ai+1](https://developers.rossum.ai/docs/using-ai-confidence-thresholds-for-automation-in-rossum?utm_source=chatgpt.com)
6.3 **\[Low\]** When fixes are applied, I want a “before vs after” narrative automatically generated, so I can communicate improvements to my team/customers. _(Nice-to-have reporting layer)_ [doc.dataiku.com](https://doc.dataiku.com/dss/latest/mlops/model-evaluations/index.html?utm_source=chatgpt.com)
* * *
### 7) Share and govern evaluation results
7.1 **\[High\]** When I need to align stakeholders, I want exportable reports (PDF/CSV) and shareable links, so decisions don’t live only inside the tool. _(Common reporting expectation across eval dashboards)_ [UiPath Documentation+1](https://docs.uipath.com/document-understanding/automation-cloud/latest/user-guide/measure?utm_source=chatgpt.com)
7.2 **\[High\]** When multiple people label/review, I want role-based permissions and approval workflows for ground truth changes, so eval integrity is protected. _(QA baseline discipline)_ [help.hyperscience.ai](https://help.hyperscience.ai/v42/docs/monitoring-model-performance?utm_source=chatgpt.com)
7.3 **\[Low\]** When dealing with sensitive docs, I want redaction/PII controls for evaluation datasets, so we can safely collaborate. _(Governance best practice; not eval-core)_ [doc.dataiku.com](https://doc.dataiku.com/dss/latest/mlops/model-evaluations/index.html?utm_source=chatgpt.com)
* * *
